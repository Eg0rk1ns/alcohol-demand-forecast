Прогнозирование спроса на алкогольную продукцию
Лабораторная работа: сравнение методов машинного обучения для прогнозирования
спроса на синтетических данных алкогольного ритейла. Демонстрирует полный
пайплайн: от генерации данных до интерактивного прогноза на заданный
пользователем горизонт, с покрытием всех категорий методов из задания —
регрессии, регуляризации, временных рядов, нейросетей, байесовских подходов,
кросс-секционных моделей и ансамблей.

Что показывает проект
Синтетический реалистичный датасет продаж алкоголя: 6 SKU, 3 года,
ежедневная частота, 6 576 строк. Заложены недельная и годовая сезонность,
праздники РФ, промо-акции (с post-promo dip), ценовая эластичность
относительно конкурента и дни out-of-stock (OOS).

Полный цикл ML-прогнозирования: EDA -> feature engineering -> baseline ->
обучение 9 моделей -> ансамбль -> интерактивный прогноз.

Сравнение метрик MAE, RMSE, WAPE на валидации и тесте для всех моделей.

Байесовские интервалы P10-P90 для оценки неопределённости.

Готовый Word-отчёт, собираемый автоматически из артефактов.

Быстрый старт
1. Окружение
python -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
..venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt

На Linux/macOS активация: source .venv/bin/activate.

2. Генерация данных
python generate_data.py

(создаёт data/sales_data.csv, 6 576 строк)

3. Полный пайплайн одной командой
.\run_all.ps1

Или по шагам:

python eda.py
python baseline.py
python model_linear.py
python model_lgbm.py
python model_prophet.py
python model_lstm.py
python model_bayesian.py
python ensemble.py
python summarize.py

4. Интерактивный прогноз
python forecast.py

Программа спросит:

Forecast horizon in days [30]: — горизонт в днях

SKU to forecast (SKU_01, ..., SKU_06 or 'all') [all]: — SKU или all

Результаты: reports/forecast_*.csv и reports/forecast_*.png.

5. Генерация Word-отчёта
python build_report.py

Создаёт Отчет_лабораторная.docx.

Как это работает — по разделам задания
Раздел 1. Классические регрессионные модели
model_linear.py (LinearRegression) и model_lgbm.py (LightGBM).
Линейная модель — простая база, обучается глобально с one-hot по SKU и
стандартизацией числовых признаков. LightGBM — промышленный градиентный
бустинг над решающими деревьями, реализован в двух вариантах:

global — одна модель на все SKU, sku как категориальный признак;

per_sku — по одной модели на SKU (классический промышленный паттерн).

Global-вариант в 6 раз больше по данным и в итоге выигрывает — это
количественное подтверждение того, что кросс-секционные модели в ритейле
эффективнее.

Раздел 2. Регуляризация
model_linear.py (Ridge, Lasso). Обе модели — та же линейная регрессия
с L2/L1-штрафом. Ridge стабилизирует коэффициенты при коррелирующих
признаках (price и discount, rolling_mean_7 и rolling_mean_28), Lasso
дополнительно обнуляет малозначимые. На синтетике с малым числом
признаков регуляризация даёт умеренный прирост или паритет с обычной
линейной моделью — важный честный результат.

Раздел 3. Модели временных рядов
model_prophet.py — Prophet от Meta. По одной модели на SKU с встроенной
годовой и недельной сезонностью, встроенными праздниками РФ
(add_country_holidays("RU")) и дополнительными регрессорами
(promo_flag, discount, price). Prophet не видит лагов и не использует
данные других SKU, но благодаря хорошему разложению
тренд + сезонность + праздники показывает результат на уровне Ridge —
это сильное подтверждение качества «из коробки».

Раздел 3* — Feature-based ML реализован в features.py + model_lgbm.py:
из исходного ряда извлекаются лаги (7/14/30 дней), скользящие средние и
стандартные отклонения (7/28 дней), календарные признаки (день недели,
месяц, день года, флаг выходного), флаг OOS. Все лаги и скользящие
сдвинуты минимум на 1 день — утечек в будущее нет.

Раздел 4. Нейронные сети
model_lstm.py — LSTM (PyTorch). По одной сети на SKU, входное окно
28 дней, признаки — прошлые продажи + промо + скидка + цены + циклические
календарные признаки (sin/cos для дня недели и месяца). Архитектура:
LSTM(32) -> Dense(1), обучение Adam, early stopping на последних 15 %
тренировочных окон. На коротких рядах (3 года) LSTM немного уступает
LightGBM, но заметно лучше линейных моделей — это типичный результат
для малых объёмов данных.

Раздел 5. Байесовский подход
model_bayesian.py — BayesianRidge. Та же архитектура, что Ridge, но
с оценкой per-sample std. Это даёт интервалы P10-P90 (при Z = 1.645),
которые бизнес использует для планирования закупок и оценки рисков.
Покрытие на тесте ~92-93 % при заявленных 90 % — интервалы честные,
не завышенные и не заниженные.

Раздел 6. Кросс-секционные модели
Реализовано через LightGBM global (model_lgbm.py) — одна модель
обучается на объединённых рядах всех SKU, sku как категориальный
признак. Плюсы: переиспользование общих паттернов (промо, календарь,
сезонность), стабильность при малом количестве данных на отдельный SKU.
В результатах global-модель обгоняет per-SKU на ~3 п.п. WAPE — это
ответ на раздел 6 задания без тяжёлых архитектур DeepAR/TFT,
избыточных для такого объёма данных.

Раздел 7. Ансамбли
ensemble.py — два варианта взвешенного среднего:

ensemble_all — все 7 моделей, веса 1 / WAPE на валидации (нормированы);

ensemble_top3 — только LightGBM global + Prophet + LSTM.

ensemble_top3 улучшает Prophet и LSTM, но не побивает LightGBM global.
ensemble_all хуже — слабые линейные модели забирают вес и шумят.
Это честный вывод: ансамбль полезен, когда базовые модели сопоставимы
по качеству; при явном доминировании одной модели взвешивание «всех
подряд» вредит.

Прогноз по запросу пользователя
forecast.py:

Обучает LightGBM global на всех доступных данных с внутренним
validation (последние 10 % дат) и early stopping.

Спрашивает у пользователя горизонт (дней) и SKU (all или конкретный).

Строит рекурсивный многошаговый прогноз: предсказание для дня t+1
становится лагом для дня t+2 и т. д.

Базовый сценарий: цена и конкурентная цена на последнем уровне,
промо и OOS не активны, ad_budget — среднее по не-промо дням.

Праздничные флаги на будущих датах берутся из реального списка
HOLIDAY_MMDD (импорт из generate_data.py) — прогноз корректно
учитывает новогодние пики и 8 марта.

Сохраняет CSV и график (последние 90 дней истории + прогноз).

Ограничения
Синтетика детерминирована — эффекты промо, сезонности и эластичности
заданы формулами без скрытых факторов. Отсюда WAPE ~10 % на лучшей
модели; на реальных данных ожидаемо 20-35 %.

Нет иерархии «регион -> магазин -> SKU», нет длинных аномалий
(пандемия, дефицит, резкие скачки цен).

Прогноз рекурсивный — ошибки накапливаются с горизонтом. Для
горизонтов > 90 дней разумнее директивное прогнозирование или
иерархическое согласование.

Не реализованы DeepAR/TFT (избыточны для 6 SKU) и stacking — это
возможные направления развития.

В model_lstm.py осталась неиспользуемая функция train_one_sku
(мёртвый код, безвредна).

Воспроизводимость
RANDOM_SEED = 42 в config.py фиксирует генератор данных и все
модели, использующие random.

Данные генерируются скриптом generate_data.py — не хранятся в git.

Все метрики и графики воспроизводятся запуском run_all.ps1.
